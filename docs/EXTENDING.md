# 模型纪元：扩展与版本约定

本项目是《模型纪元》设计方案的可玩 Alpha 实现，产品内图鉴明确展示当前规则。游戏运行不调用语言或图像模型 API。视觉由原创 SVG、CSS 与 Web Audio 实现。

## 已完成的闭环

- 12 位角色、6 个研究领域、35 张卡牌、7 种天赋。
- 8 人房间：真人加入，开局机器人补齐。单人练习走相同服务端规则。
- 12 回合，3/7/11 回合密封拍卖；拍卖→研究→评测→下一轮。
- 商店、共享卡池、锁定、刷新、备战、部署、出售、三合一升星、训练成长。
- 永久/临时算力、吞吐、显存、温度、数据质量/规模/标注/中心覆盖。
- 六阶实验室、经验购买、角色技能、天赋、羁绊、六维评分与排名。
- D1 持久化和 3 秒同步；服务器验证操作并使用 revision 比较更新，防止并发丢失。
- 客户端 actionId 防止相同操作重放；客户端期望回合/阶段防止误购下一轮商店。
- HttpOnly 会话 Cookie；跨站写入检查；密封出价与对手未公开的状态不下发。

## 内容扩展

`lib/game/content.ts` 是唯一内容目录。CardDef 定义稳定 id、阶位、类型、流派标签、研究领域、基础贡献、运行、显存、技能文案、教学说明与程序插画类型。新增卡牌在此登记；特殊效果在引擎的 acquire 中实现。不要把效果代码从客户端传给服务器执行。

Leader 定义包含角色 id、名称、主领域、主动/被动文案、配色、立绘变体和研究来源。新角色在 evaluate、act 的技能分支添加行为，并添加一个代表性的规则测试。角色立绘在 app/art.tsx 绘制；无需图像生成模型。

DOMAINS、CHALLENGES、TALENTS、ODDS 是可独立拓展的配置。挑战权重需总计 100，游戏词条和实现应同步修改。首版天赋三选一在 1/5/9 回合出现。

## 扩展边界

- 界面：app/page.tsx；艺术：app/art.tsx；主题/动效：app/globals.css。所有动画遵从 prefers-reduced-motion；音效默认关闭。
- 纯规则：lib/game/engine.ts。newGame / act / tick / evaluate / view 分别负责创建、操作、推进、评分与脱敏。服务端与测试共用规则。
- API：app/api/game/route.ts。客户端不能直接写价格、星级、分数或生命。并发更新使用单个 SQL UPDATE ... WHERE revision = ?，失败重新读取；随机状态也随游戏状态原子保存。
- 存储：db/schema.ts、lib/game/store.ts。迁移由 Drizzle 生成；已部署迁移保持不变，后续只添加新迁移。
- WebMCP：只读 read_research_arena 暴露己方状态，不接管出价或购买。支持浏览器时才注册。
- 所有存档含 version。后续规则不兼容更新应添加显式迁移或保留旧版规则分派；不要静默改写进行中的对局。

## 与完整设计文档的当前差异

首版用自动研究流程替代手动 DAG 连线；数据用四个聚合指标替代独立数据集卡槽。使用 35 张卡与通用天赋池，专属天赋合并为「专属共鸣」，尚未实现文档中每位角色的完整两条专属天赋树。副领域、硬件分槽、卡牌装备、原始论文检索和真实训练不在此版本。论文只作为概念来源，所有百分比均为游戏数值。

逐项扩展时应保持现有整局可玩，而不是让未实现功能占据虚假入口。多人对局需要访问同一个运行实例；采用访问控制的部署中，房间码不绕过访问权限。

## 校验

- `npm test`：引擎规则、完整对局模拟和 API 集成测试。
- `npm run typecheck`：类型检查。
- `npm run build`：构建 Worker 和客户端。
- 修改交互后，在桌面与触屏视口验证拖动、升星、羁绊、拍卖和结算。详见 [开发指南](DEVELOPMENT.md)。
